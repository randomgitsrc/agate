## 对这轮"计划迭代"本身的复核

在我上一版计划基础上，这次推送的版本做了 4 处改动。我逐条用实测验证了是否站得住：

| 改动 | 我的验证方式 | 结论 |
|---|---|---|
| 缓存 key 从"直接拼接命令列表"改成"先 `sort` 再拼接" | 造两组顺序不同但内容相同的命令列表，分别算 key，对比排序前后是否等价 | **真实有效**：排序前不同顺序产生不同 key（会造成不必要的缓存未命中），排序后完全一致。有意义的改进，虽然是效率问题不是正确性问题。 |
| sanity check 从"所有命令汇总数 vs 所有命令明细总数，最后统一比一次"改成"逐条命令各自比较" | 构造两条命令：A 声明 3 failed 但只提取到 2 条明细（真损坏），B 声明 1 failed 但提取到 2 条明细（相反方向的误差），验证我原方案会不会被"总数刚好抵消"掩盖 | **抓到了我自己方案的一个真实 BLOCKING 级 bug**：我原来的"最后统一比总数"设计，会被这种"一边少报一边多报、总数刚好对上"的情况完全掩盖过去，产出一份实际已损坏但被判定为"一致"的假基线。逐条比较从根上堵住了这个漏洞，这是这版最有价值的改动。 |
| 追加 EB.11/EB.12、PG.7/PG.8/PG.9 测试场景 + 缓存清理注释 | 逐条读了场景描述是否合理 | 大部分合理（EB.11 非 git 仓库、PG.7/8 全新增/全修复的边界情况都是原设计已隐含但没显式列出的场景，补充覆盖没问题） |
| 新增"落地注意"，要求同步修改 `P5-verification.md` 的"产出规格"节**和"返回前自检"节** | 实际 `grep` 了 `phase-cards/*.md` 全目录 | **不成立**：`返回前自检` 这个章节标题在整个 `phase-cards/` 目录里一次都没出现过（不只是 P5-verification.md 没有，所有阶段卡片都没有这个章节名）。这是一个没有核实过的引用——正是这个项目的评审纪律反复强调要避免的"不查实际文件、凭印象写"。P5-verification.md 实际的章节是`产出规格`/`gate 规则`/`推进条件`等，落地时应该改到这些真实存在的章节里，不是一个不存在的"返回前自检"。 |

## BLOCKING：损坏的 `pre-task-baseline.md` 会被当成"百分百新增回归"，比"文件缺失"更差

`check-gate.sh` P5 分支现有设计只判断文件是否存在（`[ -f "$BASELINE" ]`），不校验内容是否合法。EB.12 场景里写的预期行为是"PRE_LIST 提取为空，所有 post 失败视为新增"——顺着这个逻辑往下推：如果基线文件因为某种原因内容损坏（比如磁盘/编辑冲突/手误改动，导致 `sed` 提取不到 fail-list 代码块），`comm -13` 会拿一个空的 PRE_LIST 去和 post 比较，**结果是当前所有失败（不管是不是真的预存）全部被判定为"新增回归"，触发 `exit 1` 硬拦截**。

这比"`pre-task-baseline.md` 干脆不存在"的后果更严重——文件缺失时会优雅降级成原有的 `exit 2`（不阻塞，只是没有机械判定），但文件存在却损坏时，反而会制造一次**看起来证据确凿、实际是基础设施问题伪装成的"回归"**，把主 Agent 的排查方向带偏（会去找"我是不是引入了新 bug"，而不是"基线文件是不是坏了"）。这正是这份计划自己在 0.5 节承认过的哲学——"错误的'看似干净'比'没有'更危险"——用在捕获脚本自己身上是对的，但同一条原则应该同样适用到 P5 读取基线文件这一侧，目前的设计遗漏了这一半。

**建议修复**：给 `pre-task-baseline.md` 的合法性加一个廉价校验——比如要求文件必须包含 `captured_at_commit:` 这一行 frontmatter 标记（捕获脚本本来就会写这一行）。P5 gate 读取时先检查这个标记是否存在；不存在就判定为"文件无效"，和"文件缺失"走同一条优雅降级路径（`exit 2`），而不是把提取失败悄悄等价于"基线是空的、所以一切都是新增"。

## 非阻塞：commit message 描述的"独立评审"没有对应的评审文件一起推送

这次推送里只有计划文档本身的修订，没有看到一份类似我之前那份 `review-env-baseline-plan-20260725.md` 的独立评审记录文件。commit message 里描述了评审发现了什么、改了什么，但这些内容目前只存在于 commit message 里，不在仓库的可追溯文档中——这和这个项目一贯的纪律（P6 provenance、self-gate review 都要求落盘成文件，不能只在 commit message 里叙述）不一致。不阻塞这个计划本身推进，但建议以后的评审轮次把评审文件也一并提交，保持"一切经过校验的事实都要有可追溯书面记录"这条一直在坚持的原则。

```markdown
## P0-brief 时效性自检（漂移判据）

P0-brief 写完不等于永久有效。**立项时间与实际启动/恢复时间存在间隔**（跨会话恢复、任务被搁置后重启、从 PAUSED 恢复）时，推进 P1 前必须对照下面的判据做一次时效性校验，判断 P0-brief 是否已漂移。

**严重漂移**（命中任一条 → 回 P0 重新立项 / 重做可行性分析，不允许带着失效前提推进）：

1. `task` 字段描述的目标方案本身不再成立（所需修改的技术路线 / 架构已变化）
2. `executor_env` 声明的平台 / 运行时前提不再成立（声明的 CI 环境或工具链已下线、大版本不兼容）
3. `known_risks` 中被判定为"已解决前提"的条目实际仍未解决；或反之已被其他任务解决，导致本任务范围重叠 / 失效

**轻微漂移**（不命中以上任一条 → 更新 P0-brief 对应字段 + 标注 `[P0_STALE]` 后继续，不阻塞）：

4. 局部细节变化（文件路径、依赖版本号、单个工具调用方式）不影响任务方案选择
5. `env_constraints` 的具体值需刷新（如 `debug_env` 端口变化）但环境类型未变

**判定流程**：对照 1-3 逐条排查 → 命中任一条 = 严重（回 P0）；全部不命中 = 轻微（更新字段 + `[P0_STALE]` 标注 + 继续 P1）。

⚠️ 不要用"距立项过了几天"当判据——时间与漂移程度不相关：隔 2 天技术路线切换是严重漂移，搁置 60 天但项目没变只是轻微。判据看的是**前提是否还成立**，不是过了多久。

标注格式与 P1 阶段的处理规则（阻塞 / 记录二选一）见 P1 卡片「P0-brief 时效性质疑」节。

```

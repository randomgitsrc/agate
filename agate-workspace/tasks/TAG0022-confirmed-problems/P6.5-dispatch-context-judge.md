# P6.5-dispatch-context-judge — TAG0022 验收独立复核

> 派发对象：judge（P6.5 独立裁判，fresh context 逐条重验全部 BDD）。这是本轮的强制指令，不是参考信息。
> 任务目录：`{AGATE_WORKSPACE}/tasks/TAG0022-confirmed-problems/`

## 目标

以 fresh context 独立复核 TAG0022 的 P1 需求基线全部 BDD（BDD-1..10，**零挑验**——含已判 PASS 项），只信证据文件与 git log，产出 `P6.5-judge-verdict.md`。

## 上游关联

- 需求基线：`P1-requirements.md`
- 方案设计（仅验收相关节，如 §3 完成标准 / §4.4 实证计划）：`P2-design.md`
- 验收证据目录：`P6-evidence/`
- 任务状态：`.state.yaml`
- 事件账本：`gate-events.jsonl`
- 本角色自身产出（复核时若已存在）：`P6.5-judge-verdict.md`
- 另授 **git log 查询权**（核对执行留痕，非路径输入）

## 输入文件

1. `P1-requirements.md`（BDD-1..10 原文）
2. `P2-design.md`（仅 §3 完成标准 / §4.4 实证计划节）
3. `P6-evidence/` 目录（全部证据文件）
4. `.state.yaml`（任务状态）
5. `gate-events.jsonl`（事件账本）
6. `P6.5-judge-verdict.md`（本角色产出）

## 复核任务（逐条，零挑验）

对 P1-requirements.md 中每条 `#### BDD-NN:`（BDD-1..10），独立核验：
- BDD 的可判定判据是什么（Given/When/Then）
- 证据文件是否真实存在且非空、是否支持该 BDD 的结论
- 用 git log 核对执行留痕（相关提交是否存在、时间线是否合理）
- 每条结论必须引用 P6-evidence/ 下真实存在且非空的证据文件

**禁止**：「看起来没问题」式结论；结论与证据不符却放行；引用不存在的证据路径。

## 三档预算（超限诚实降级）

轮次 ≤2 / token 100k / 时间 30min。任一预算耗尽 → 立即停止，按已验条目落盘 verdict，必须 `status: needs-revision` + `partial: true`，禁止静默放行。

正文每条 BDD 一行：`- (PASS|FAIL|NEEDS-REVISION) BDD-NN: 描述 (证据路径)`；`criteria_total` 必须等于 P1 `#### BDD-NN:` 标题数（10）。

## 环境约束

Linux；/tmp 只读；bash 一律 timeout；双工作区纪律（只读消费，写操作仅限 P6.5-judge-verdict.md 与 P6.5-progress.md）。状态标记：`[PROD_TOUCHED]`/`[PROD_NOT_TOUCHED]`。git log 查询可用（timeout 包裹）。

## 分阶段落盘

每复核完一个 BDD，追加写 `P6.5-progress.md`（task 目录内）。

## 返回给我

只返回两行：① P6.5-judge-verdict.md 路径；② status + criteria_passed/criteria_total + 一句话摘要。绝不返回文件全文。

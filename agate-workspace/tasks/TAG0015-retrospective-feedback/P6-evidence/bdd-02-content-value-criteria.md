# BDD-2 证据：模板声明内容价值标准

文件：`agate/assets/templates/retrospective-template.md`

## Then 子句逐项核对

Then 要求：模板文件包含一个明确小节，枚举三条内容价值标准（机制缺口 / 可复用模式 / 归因到
可行动层面的问题），可通过 grep 该小节标题与三条枚举文本校验存在性。

| 要求 | 实际（行号） |
|------|-------------|
| 明确小节 | `## 填写前必读：内容价值标准`（L8） |
| 三条枚举①机制缺口 | L13 `1. **机制缺口**——agate 协议/脚本/模板本身没有定义或覆盖到的情况，导致问题发生` |
| 三条枚举②可复用模式 | L14 `2. **可复用模式**——本次任务中验证有效、值得固化进协议或项目资产的做法` |
| 三条枚举③归因到可行动层面的问题 | L15 `3. **归因到可行动层面的问题**——不是笼统吐槽，而是能落到具体文件/字段/gate 的改进点` |

且该小节确认放在"填写前必读"位置（P2-design.md 明确"不是产出文档要填的正文节"），符合
BDD-2 检查"模板文件本身是否定义标准"而非检查产出文档的语义。

## 原文摘录

```
## 填写前必读：内容价值标准

> 复盘不是流水账（不要复述 P1-P8 过程），也不是自我表扬（不要只写做得好的）。
> 值得写的内容只有三类，撰写前先对照这三条判断"这段话是否值得写"：

1. **机制缺口**——agate 协议/脚本/模板本身没有定义或覆盖到的情况，导致问题发生
2. **可复用模式**——本次任务中验证有效、值得固化进协议或项目资产的做法
3. **归因到可行动层面的问题**——不是笼统吐槽，而是能落到具体文件/字段/gate 的改进点

不满足以上三条任一条的内容（如单纯复述执行步骤）不建议写入复盘正文。
```

## 判定

**满足**——小节标题存在、三条枚举文本逐字存在，且带有反面案例（"不满足...不建议写入"）
增强可执行性，超出 Then 字面最低要求。

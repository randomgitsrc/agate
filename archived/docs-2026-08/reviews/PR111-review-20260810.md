## 二、阻塞项 1：任务目录混进 PR（CI 红根因）

### 现象

CI consistency 报 6 ERROR，全部来自 `docs/tasks/T001-v2.0-structured/`（T001 dogfooding 的 101 个任务文件）：

```
❌ YAML 代码块无法解析: docs/tasks/T001-v2.0-structured/.archived/.../P6-evidence/bdd-04.md:8
❌ 协议文件引用了不存在的文件: agate-v2.0-structured-phase1-20260809.md [P0-brief.md:117]
❌ 协议文件引用了不存在的文件: agate-test-plan-2026-07-01.md [P5-test-results/unit.md:759]（×4 处）
```

### 根因

任务目录是 T001 用 agate 流程改造 agate 的**完整产物**（P0-brief、P1-requirements、P6-evidence、.archived 等），**不属于协议本体变更**。它引用了已不存在的 plan 文件（`agate-v2.0-structured-phase1-20260809.md` 被 reset、`agate-test-plan-2026-07-01.md` 历史遗留），且 `.archived/` 下有故意构造的坏 YAML（测试用例）。

### 顺带发现的 bug（历史遗留）

`check-protocol-consistency.py:108` 的 `iter_md_files` 排除逻辑：
```python
if "archived" in p.parts:  # 但实际目录名是 ".archived"（带点）
```
`'.archived' in p.parts` = True，但 `'archived' in p.parts` = **False**——**排除从未生效**。main 上也有此 bug，只因 main 从无 `.archived` 任务目录而未暴露。本次 PR 带上任务目录使其暴露。

### 处置（已执行）

将任务目录**归档**到 `docs/archived/tasks/T001-v2.0-structured/`（git mv）：
- 从协议变更移除 → consistency 不再扫到 → CI 绿
- 归档后路径含 `archived`（不带点）→ 被 iter_md_files **正确排除**（规避了 `.archived` bug）
- 任务记录保留（归档而非删除）

**已验证**：归档后本地 consistency 全过。

## 三、已知偏离：check-pruning.sh 6 字段未走双读工具（已澄清，非阻塞）

### 现象（原始观察）

worktree 全量 bats 有 3 个失败（P2.6e/P2.52/P2.52b），当时归因于 check-pruning.sh 未迁移。

### 真实根因（T001 团队澄清 + 实测确认）

**3 个测试失败的直接原因不是 check-pruning.sh 未迁移**，而是审查期间在共享 worktree 做的任务目录归档 `git mv` 处于"已暂存未 commit"中间态——`check-pruning.sh` 的源码计数检查读 `git diff --cached`，101 个待提交的 rename 文件把源码数顶过阈值。**归档 commit 后 3 个测试立即恢复，605/605 全绿。**

### 已确认的事实（两部分）

**事实 A：check-pruning.sh 确实有 6 个字段未走 `agate-md-field-get.py` 双读工具**

| 字段 | check-pruning.sh 行号 | 读取方式 |
|------|----------------------|---------|
| `override:` | L23 | `grep -c '^override:'` |
| `implicit_coupling:` | L76/81 | `grep -qE '^implicit_coupling:'` |
| `coupling_checklist:` | L82 | `grep -qE '^coupling_checklist:\s*\['` |
| `internal_only:` | L90 | `grep -qE '^internal_only:\s*true'` |
| `internal_only_reason:` | L92 | `grep -qE '^internal_only_reason:'` |
| `跳过风险:` | L100 | `grep -qE '跳过风险:'` |

**事实 B：这是 T001 P7 已审查标注的已知偏离，非本次失败原因**

T001 的 P7-consistency.md（归档于 `docs/archived/tasks/T001-v2.0-structured/P7-consistency.md` L29/L33）已对 check-gate.sh 和 check-pruning.sh 的同类未迁移做出 `DESIGN_GAP_REVIEWED: 接受` 裁决：
- `agate-frontmatter-check.py` 的 schema 校验（P1 required = risk_level/phases 等，含可选字段规则）已在 pre-commit 层拦截坏格式（全角冒号/缩进/枚举错误）
- check-pruning.sh 未迁移**不产生实际解析可靠性缺口**（frontmatter 恒在文件最前且顶格书写，`^field:` 恰好命中 frontmatter 内行，功能等价）
- 仅属"统一实现路径"的设计偏离（P2 §3.1.2 字面要求全部迁移），不构成 BLOCKER

### 修正结论

原 review 将此事定性为"结构化改造没兑现（Important）"是**错误的**——把 3 个测试失败误归因于此，且未查证 T001 P7 的已知偏离记录。实际是：审查自身操作干扰（git mv 未 commit）+ 已审查标注的设计偏离，两者均不阻塞合并。

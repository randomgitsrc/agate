# agate 商业分析与建议（2026-08-11）

> 基于：agate v0.40.2 实际数据（采集于本机）+ Manus 官方页面/API/对比页（webfetch 实时核实）
> 结论先行：**agate 不应作为"通用 agent 产品"卖，而应作为"AI 编码质量流程平台"定位——它和 Manus 是相反哲学，但恰好互补，agate 的差异化恰是 Manus 的短板。**

---

## 1. 参照物核实：Manus 是什么（2026-08 实时数据）

### 1.1 关键事实
- **已被 Meta 收购**（官网横幅"Manus is now part of Meta"）——通用 agent 赛道已巨头化
- 定位：**"Less structure, more intelligence"**（少结构，多智能）
- 产品：Web app + Desktop + Mobile + API + Slack 集成 + Team plan（SSO）
- 能力：自主规划执行、生产级交付（网站/应用/报告）、100+ 文件上下文、24/7 后台任务、Wide Research（并行研究 100+ 来源）、Browser Operator
- API：REST（`api.manus.ai`），Tasks/Projects/Files/Webhooks/Agents/Structured Output
- 对比定位：VS ChatGPT（"能行动 vs 只能建议"）、VS Lovable、VS Replit

### 1.2 哲学核心
Manus 的卖点是**"你给目标，它自主找出路径"**——低结构、高自主、交付成果。这正好是 agate 的**反面**。

### 1.3 对 agate 的启示
Manus 已经证明"通用 agent 云服务"是一个被巨头（Meta）占领、需要巨额投入（基础设施/算力/获客）的市场。**agate 不该进入这个市场。**

## 3. agate vs Manus：哲学对比（决定商业模式）

| 维度 | Manus | agate |
|------|-------|-------|
| 设计哲学 | **少结构，多智能** | **强结构，多门禁** |
| 关注点 | 自主完成任务 | 保证完成质量 |
| 用户 | 要结果的人 | 要可靠性的工程师/团队 |
| 交付 | 成果文件 | 代码 + 流程证据 |
| 质量保证 | 靠模型能力 + 运气 | P0-P8 gate + 独立评审 + 证据链 |
| 可回退 | 失败基本重做 | P6→P5→P4 规范回退 |
| 可审计 | 黑盒 | 全流程留痕 |
| 可私有化 | 否（云服务） | 是（开源自托管） |

**关键洞察**：Manus 的卖点（"自主、少结构"）恰恰是 agate 刻意**不做**的——agate 用"结构 + 门禁"补偿模型的不可靠。**这不是劣势，是 agate 的差异化。**

## 4. agate 可卖的价值主张

### 4.1 核心主张：**"AI 写的代码，上线前就知道质量"**

对企业的价值不是"AI 能写代码"（Manus/Copilot 都能），而是：
- **可信**：每阶段 gate 验证（P5 全量重跑、P6 证据核对），不是"交给你验收才发现错"
- **可回退**：出错能定向修复（retreat 机制），不浪费
- **可审计**：全流程留痕（.state.yaml/复盘/DESIGN_GAP 追踪），合规场景必备
- **可私有化**：无数据出境，金融/医疗/军工可选

### 4.2 谁愿意为这个付钱
- **合规敏感行业**（金融/医疗/军工/政府）：AI 编码质量 + 可审计性是硬需求
- **大型团队**（AI 编码但怕质量失控）：需要一个"质量流程层"
- **平台/工具公司**：把 agate 集成进自家 AI 编码产品

### 4.3 一句话定位
**agate = 面向软件工程团队的 AI 编码质量流程平台**。Manus 是"AI 帮你做"，agate 是"AI 做了，我确保它做对"。

## 5. 商业模式建议（三种路径）

### 路径 A：开源 + 企业版（推荐，成本最低）
- **免费**：协议本体（MIT 开源，引流）
- **付费**：企业版 = 闭源增强（人类可读看板 + 私有化部署 + 专属支持 + 合规报告）
- 定价：**$100-500/人/年** 或 **$5k-20k/年/团队**
- 对标：SonarQube（代码质量平台）定价逻辑
- 理由：agate 的价值是"质量流程"，企业为质量 + 合规付费

### 路径 B：开源 + 托管 SaaS（中等投入）
- **免费**：协议本体
- **付费**：托管编排（云端跑 agate + 接 Claude/GPT API + UI 看板）
- 定价：**$20-50/人/月**
- 对标：Copilot/Cursor 定价逻辑
- 理由：复用 Manus 验证过的"托管交付"模式，但差异化在"质量门禁"
- 风险：需要基础设施 + 模型 API 成本

### 路径 C：咨询服务（零投入起步）
- **一次性**：帮团队接入 + 定制 gate + 培训（$2k-20k/次）
- 理由：118 个复盘是独有方法论资产，AI 编码质量咨询是热门话题
- 定位：验证市场 + 攒客户，再转 A/B

## 6. 产品化最大缺口：人类可读看板

**agate 目前是给 agent 读的协议，没有给人类看的界面。** 商业化必须补：

| 缺口 | 现状 | 需要 |
|------|------|------|
| 任务状态看板 | .state.yaml 需手读 | Web UI：任务列表 + 当前阶段 + gate 结果 |
| gate 结果可视化 | 脚本输出 | 面板：P0-P8 进度 + PASS/FAIL + 证据链 |
| 团队协作 | 无 | 多任务 + 权限 + 审计日志 |
| 报告 | 无 | 一键生成"质量报告"（合规用） |

**这个看板是 agate 从"工具"变"产品"的关键**——Manus 有完整 UI，agate 要让非 agent 用户也能看见"可靠性在哪"。

---

## 7. 建议的下一步

1. **短期（0-2 月）**：路径 C 起步——用 118 复盘 + 协议做咨询服务，验证企业需求，攒 3-5 个付费客户
2. **中期（2-6 月）**：补人类看板 MVP（任务状态 + gate 结果）——这是产品化分水岭
3. **长期（6 月+）**：基于客户反馈选 A（企业版）或 B（SaaS）

**风险提示**：
- Manus 被 Meta 收购说明通用 agent 是巨头游戏，agate 不碰
- agate 的"质量流程"价值需要教育市场（企业未必懂 P0-P8 的价值）——看板 + 咨询是教育手段
- 0 stars 意味着还没验证外部需求，**建议先在技术社区推广（开源引流）再商业化**

---

## 8. 一句话总结

**agate 不该卖"AI 帮你做事"（那是 Manus/Meta 的战场），该卖"AI 做的事，我确保它可靠、可审计、可私有化"。这是 Manus 刻意不做（少结构）的部分，恰好是 agate 的护城河。** 产品化最大缺口是人类看板，最短路径是咨询起步验证需求。
